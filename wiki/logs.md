## iter 1
Created a new pattern page (patterns/member-id-generation-format.md) after observing that all 6 sampled traces for the 'generate internal member ID' task failed, each because the agent fabricated its own plausible-sounding ID scheme instead of applying a single consistent rule. By reverse-engineering the expected outputs across all examples, the actual rule was determined to be: first 3 letters of surname (or fewer if shorter) + last 2 digits of birth year + first letter of given name, with no separators or sequence numbers. The page documents the symptom (confident but varying fabricated formats), the root cause (treating underspecified formatting tasks as license to invent rather than infer/recall a fixed convention), the evidence (task ids t1-t6), and a concrete workaround rule with verification against all sampled cases so future attempts apply the correct deterministic format.
